# Архітектура dionis.plus

Цей документ описує архітектуру платформи dionis.plus — PWA додатка для знайомств LGBTQ+ спільноти в Україні.

## Загальний огляд

dionis.plus побудований як монорепозиторій з трьома основними компонентами:

1. **Client (React PWA)** — Progressive Web App з React 18, Tailwind CSS v4, та Framer Motion
2. **Server (Express API)** — RESTful API з автентифікацією, управлінням профілями та завантаженням зображень
3. **Shared (Schema)** — Спільна Drizzle ORM схема та TypeScript типи

## Компоненти системи

### 1. Client (React PWA)

**Розташування:** `client/`

**Технології:**
- React 18.3+ з TypeScript
- Vite 5 (збірка та dev server)
- Tailwind CSS v4 (стилізація)
- Framer Motion (анімації)
- Wouter (роутинг)
- React Hook Form + Zod (форми та валідація)
- Radix UI (UI примітиви)
- TanStack Query (керування серверним станом)

**Структура:**
```
client/
├── index.html          # Точка входу, PWA meta tags
└── src/
    ├── main.tsx        # React точка входу
    ├── App.tsx         # Головний компонент з роутингом
    ├── pages/          # Сторінки додатка
    ├── components/     # Reusable React компоненти
    ├── hooks/          # Custom React hooks
    ├── lib/            # Утиліти клієнта
    └── styles/         # Глобальні стилі
```

**Особливості:**
- Підтримка PWA з offline-first підходом
- Адаптивний дизайн для мобільних пристроїв
- Dark mode за замовчуванням
- Оптимістичні оновлення з TanStack Query
- Інтеграція з service worker для кешування

### 2. Server (Express API)

**Розташування:** `server/`

**Технології:**
- Express 4.21+ з TypeScript
- Drizzle ORM (PostgreSQL через pg driver)
- Express Session (сесії з PostgreSQL store)
- Passport.js (локальна автентифікація)
- Sharp (обробка зображень)
- TensorFlow.js + NsfwSpy (NSFW модерація)
- Multer (завантаження файлів)
- WebSocket (real-time features)

**Структура:**
```
server/
├── index.ts        # Точка входу, Express app setup
├── routes.ts       # API endpoints (auth, profiles, uploads)
├── db.ts          # PostgreSQL connection pool
├── upload.ts       # Image upload & compression logic
├── nsfw.ts         # NSFW модерація з TensorFlow
├── storage.ts      # ImgBB integration
├── vite.ts         # Vite middleware для dev режиму
├── pwaAssets.ts    # PWA assets serving
└── apiError.ts     # Стандартизовані помилки API
```

**API Endpoints:**

**Автентифікація:**
- `POST /api/auth/register` — реєстрація нового користувача
- `POST /api/auth/login` — вхід
- `POST /api/auth/logout` — вихід
- `GET /api/auth/check` — перевірка поточної сесії

**Профілі:**
- `GET /api/profiles` — список профілів (з фільтрами)
- `GET /api/profiles/:id` — отримати профіль за ID
- `POST /api/profiles` — створити/оновити профіль поточного користувача
- `DELETE /api/profiles/:id` — видалити профіль (власний)

**Завантаження зображень:**
- `POST /api/upload` — завантажити зображення з NSFW модерацією
  - Стискає зображення до max 1920x1920, якість 85%
  - Класифікує з NsfwSpy (відхиляє, якщо NSFW > 60%)
  - Завантажує до ImgBB
  - Повертає публічний URL

**Здоров'я:**
- `GET /api/health` — статус сервера та БД

### 3. Shared (Schema & Types)

**Розташування:** `shared/`

**Технології:**
- Drizzle ORM (схема PostgreSQL)
- Zod (валідація та типи runtime)

**Схема бази даних:**

```typescript
// users table
{
  id: uuid (primary key, generated by pgcrypto)
  username: varchar(255), unique, not null
  email: text, unique, nullable
  password_hash: text, not null
  created_at: timestamp, default now()
}

// profiles table
{
  id: uuid (primary key)
  user_id: uuid (foreign key -> users.id, CASCADE)
  
  // Особиста інформація (крок 1-2)
  display_name: varchar(100)
  birth_date: date
  city: varchar(100)
  bio: text
  
  // Фото (крок 3)
  photos: text[] (масив URLs)
  
  // Налаштування (крок 4-10)
  is_commercial: boolean
  commercial_rates: jsonb
  orientation: varchar(50)
  role: varchar(50)
  body_type: varchar(50)
  interests: text[]
  
  // Контакти
  telegram: varchar(100)
  phone: varchar(20)
  
  // Мета-дані
  created_at: timestamp
  updated_at: timestamp
}
```

## Потік даних

### 1. Автентифікація

```
Client                    Server                     Database
  |                         |                            |
  |--POST /api/auth/login-->|                            |
  |  {username, password}   |                            |
  |                         |--SELECT user WHERE...----->|
  |                         |<--user row-----------------|
  |                         | (verify password)          |
  |                         | (create session)           |
  |<--{user, session}-------|                            |
  |                         |                            |
```

Сесії зберігаються в PostgreSQL через `connect-pg-simple` store.

### 2. Створення профілю (10 кроків)

```
Client (Multi-step form)  Server                     Database
  |                         |                            |
  |--POST /api/profiles---->|                            |
  |  {step1: {...}}        |                            |
  |                         |--INSERT/UPDATE profile---->|
  |<--{profileId}-----------|<--profile row--------------|
  |                         |                            |
  |--POST /api/upload------>|                            |
  |  FormData(image)        |                            |
  |                         | (compress with Sharp)      |
  |                         | (classify with NSFW)       |
  |                         | (upload to ImgBB)          |
  |<--{imageUrl}------------|                            |
  |                         |                            |
  |--POST /api/profiles---->|                            |
  |  {step3: {photos}}     |                            |
  |                         |--UPDATE profile.photos---->|
  |<--{updated profile}-----|<--profile row--------------|
```

### 3. Пошук профілів

```
Client                    Server                     Database
  |                         |                            |
  |--GET /api/profiles----->|                            |
  |  ?city=Kyiv&role=top   |                            |
  |                         |--SELECT profiles WHERE---->|
  |                         |<--filtered rows------------|
  |<--[{profile}, ...]------|                            |
```

## Деплой на Railway

### Build Process

Railway виконує наступні кроки:

1. **Install:** `npm install --omit=dev`
   - Встановлює runtime залежності
   - TensorFlow.js та Sharp збираються нативно

2. **Build:** `npm run build`
   - Vite збирає клієнт у `dist/public/`
   - esbuild збирає сервер у `dist/index.js`

3. **Start:** `npm start`
   - Запускає `dist/index.js`
   - Роздає статику з `dist/public/`

### Конфігурація Railway

**Build Command:**
```bash
npm install --omit=dev && npm run build
```

**Start Command:**
```bash
npm start
```

**Environment Variables:**
- `DATABASE_URL` — Railway PostgreSQL URL (автоматично)
- `SESSION_SECRET` — генеруйте через `openssl rand -base64 32`
- `CLIENT_ORIGIN` — `https://<your-app>.up.railway.app`
- `SOCKET_ORIGIN` — `https://<your-app>.up.railway.app`
- `IMGBB_API_KEY` — з ImgBB dashboard
- `MAP_PROVIDER_KEY` — Google Maps або Mapbox API key
- `PORT` — автоматично встановлюється Railway
- `TF_CPP_MIN_LOG_LEVEL=2` — зменшує логи TensorFlow

### SSL Configuration

Сервер автоматично визначає середовище та налаштовує SSL:

- **Production (non-localhost):** `ssl: { rejectUnauthorized: false, checkServerIdentity: () => undefined }`
- **Development (localhost):** SSL вимкнений

## Розширення функціоналу

### Додавання нового API endpoint

1. **Створити роут у `server/routes.ts`:**

```typescript
router.post('/api/new-feature', async (req, res) => {
  try {
    const data = await db.select().from(newTable);
    res.json(data);
  } catch (error) {
    handleApiError(error, res);
  }
});
```

2. **Додати схему до `shared/schema.ts`:**

```typescript
export const newTable = pgTable('new_table', {
  id: varchar('id', { length: 255 }).primaryKey(),
  // ... columns
});
```

3. **Створити міграцію у `lib/db/migrations.ts`:**

```typescript
await db.execute(sql`
  CREATE TABLE IF NOT EXISTS new_table (
    id VARCHAR(255) PRIMARY KEY,
    ...
  )
`);
```

4. **Використати на клієнті з TanStack Query:**

```typescript
const { data } = useQuery({
  queryKey: ['newFeature'],
  queryFn: async () => {
    const res = await fetch('/api/new-feature');
    return res.json();
  }
});
```

### Додавання WebSocket функціоналу

Сервер вже включає `ws` пакет. Для реального часу:

1. **Налаштуйте WebSocket server у `server/index.ts`:**

```typescript
import { WebSocketServer } from 'ws';

const wss = new WebSocketServer({ server: httpServer });

wss.on('connection', (ws) => {
  ws.on('message', (message) => {
    // Handle incoming messages
    wss.clients.forEach(client => {
      if (client.readyState === WebSocket.OPEN) {
        client.send(message);
      }
    });
  });
});
```

2. **Підключіться з клієнта:**

```typescript
const ws = new WebSocket('ws://localhost:5000');
ws.onmessage = (event) => {
  console.log('Message:', event.data);
};
```

### Додавання нових сторінок

1. **Створити компонент у `client/src/pages/`:**

## Troubleshooting

### База даних недоступна
- Перевірте `DATABASE_URL` у `.env`
- Переконайтеся, що PostgreSQL запущений
- Перевірте логи Railway для помилок підключення

### TensorFlow помилки
- Встановіть `TF_CPP_MIN_LOG_LEVEL=2`
- Перевірте, що @tensorflow/tfjs-node встановлений
- Railway може потребувати спеціальних buildpacks для TensorFlow

### Vite build помилки
- Очистіть `dist/` та `node_modules/.vite`
- Запустіть `npm run build` знову
- Перевірте, що всі шляхи імпортів коректні

### Session втрачаються
- Перевірте `SESSION_SECRET` env var
- Переконайтеся, що connect-pg-simple налаштований з правильним DATABASE_URL
- Перевірте, що cookies працюють (SameSite, Secure в production)
